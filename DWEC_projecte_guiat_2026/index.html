    La Vall en Joc: projecte guiat de JavaScript

    1. El repte

    L'associació juvenil del poble prepara La Vall en Joc, una jornada de reptes de lògica, fotografia, esport i patrimoni. Necessita una aplicació perquè els equips consulten les proves, organitzen el seu itinerari i preparen la inscripció.

    Durant 10 setmanes construireu una aplicació d'una sola pàgina (SPA) amb HTML, CSS i JavaScript. Començareu amb dades en la consola i acabareu amb una aplicació interactiva, amb persistència i mapa.

    Abast de la guia

    Treballarem les UD1, UD2 i UD3. No utilitzarem l'annex de BOM, AJAX, Vue ni un servidor de dades. La inscripció serà una simulació local: no s'enviarà a cap associació.

    Es mantenen localStorage, cookies i geolocalització perquè formen part de la UD3. No incorporarem el rellotge ni el carrusel temporitzat del projecte ciclista.

    Regles de la jornada

    • Cada itinerari conté entre 3 i 5 reptes diferents.
    • Ha d'incloure almenys 2 categories.
    • La suma de les duracions no pot superar 180 minuts, inclosos els extrems: 180 és vàlid.
    • Les duracions són estimacions didàctiques de les proves. No calcularem desplaçaments ni rutes reals.
    • Els equips tenen entre 2 i 6 participants.
    • Es poden preparar itineraris incomplets, però només es pot confirmar una inscripció amb un itinerari vàlid.
    • La puntuació és orientativa: seleccionar una prova no significa haver-la superada.

    Resultat final esperat

    Una única pàgina amb el títol del projecte, un catàleg de huit reptes, controls de cerca i filtratge, una vista de detall, un itinerari ordenable, un resum, un formulari i un mapa. Tot el contingut que depén de les dades es genera amb JavaScript.

    Una persona ha de poder buscar una prova, consultar-la, afegir-la a l'itinerari, reordenar-lo, recarregar la pàgina i recuperar la selecció. Si denega la ubicació, ha de poder continuar utilitzant l'aplicació.

    El recorregut de l'usuari

    Figura 1. Recorregut principal de La Vall en Joc. Prem la imatge per a veure-la ampliada.

    1. Explora: busca i filtra les proves del catàleg.
    2. Tria: consulta el detall i afegeix reptes sense duplicar-los.
    3. Organitza: ordena la selecció amb botons o arrossegament.
    4. Valida: comprova els 3–5 reptes, les dues categories, el màxim de 180 minuts i el formulari d'un equip de 2–6 participants. Si hi ha errors, corregeix-los abans de continuar.
    5. Confirma: genera el justificant local. No s'envien dades a un servidor.

    El guardat acompanya els canvis de l'itinerari; no cal confirmar la inscripció per a recuperar-lo després de recarregar. El mapa i la ubicació són una consulta complementària, no un requisit per a inscriure's.

    Com interpretar les imatges

    Les dues imatges són recursos il·lustratius generats amb IA. La maqueta simplifica el catàleg a tres fitxes i el formulari a alguns camps perquè s'entenga la distribució. La versió que programareu ha de contindre les huit proves i tots els camps de la setmana 6; el botó de confirmar només s'habilita quan totes les validacions passen.

    Els llocs, les fotografies, l'adreça del navegador i el mapa són ficticis. Els noms addicionals de la infografia, el codi QR i els enllaços decoratius de la maqueta no són requisits del projecte. Utilitzeu les dades de dades.js i les regles escrites en aquesta guia.

    No cal reproduir aquest CSS. En mòbil podeu disposar les zones en una sola columna, mantenint l'ordre catàleg, itinerari, formulari i mapa.

    2. Organització i temporalització

    Aquest projecte és una activitat d’aprenentatge sense qualificació. Les comprovacions i la demostració final serveixen per a revisar el funcionament i entendre el codi.

    Previsió: 3 hores setmanals, 30 hores en total. És una hipòtesi de treball que el professorat pot ajustar a l'horari real. El projecte es desenvolupa en classe; les ampliacions no són necessàries per a completar-lo.

    export function resumir(seleccio = []) {
  const categories = [];
  let minuts = 0;
  let punts = 0;
  for (const repte of seleccio) {
    minuts += repte.minuts;
    punts += repte.punts;
    if (!categories.includes(repte.categoria)) {
      categories.push(repte.categoria);
    }
  }
  return { quantitat: seleccio.length, minuts, punts, categories };
}

export function validarItinerari(seleccio = []) {
  const resum = resumir(seleccio);
  const errors = [];
  if (resum.quantitat < 3 || resum.quantitat > 5) {
    errors.push("Tria entre 3 i 5 reptes.");
  }
  if (resum.categories.length < 2) errors.push("Tria almenys 2 categories.");
  if (resum.minuts > 180) errors.push("No pots superar els 180 minuts.");
  const ids = seleccio.map(repte => repte.id);
  if (ids.some((id, index) => ids.indexOf(id) !== index)) {
    errors.push("No pots repetir reptes.");
  }
  return errors;
}

    export function pintarCataleg(llista, contenidor) {
  contenidor.replaceChildren();
  if (llista.length === 0) {
    contenidor.textContent = "No hi ha reptes amb aquests filtres.";
    return;
  }
  for (const repte of llista) {
    const article = document.createElement("article");
    article.dataset.id = repte.id;
    const titol = document.createElement("h2");
    titol.textContent = repte.nom;
    const resum = document.createElement("p");
    resum.textContent = `${repte.minuts} minuts · ${repte.punts} punts`;
    const imatge = document.createElement("img");
    imatge.src = repte.imatge;

    descripcio.textContent = repte.descripcio;
    article.append(titol, imatge, resum, descripcio);

      boto.type = "button";
      boto.dataset.accio = accio;
      boto.textContent = text;
      article.append(boto);
    }
    contenidor.append(article);
  }
}

    const cataleg = document.querySelector("#cataleg");
const cerca = document.querySelector("#cerca");
const categoria = document.querySelector("#categoria");
const ordre = document.querySelector("#ordre");

function actualitzarCataleg() {
  const text = cerca.value.trim().toLocaleLowerCase("ca");
  const visibles = reptes.filter(repte =>
    repte.nom.toLocaleLowerCase("ca").includes(text) &&
    (categoria.value === "totes" || repte.categoria === categoria.value)
  );
  visibles.sort((a, b) => {
    switch (ordre.value) {
      case "minuts": return a.minuts - b.minuts;
      case "punts": return b.punts - a.punts;
      default: return a.nom.localeCompare(b.nom, "ca");
    }
  });
  pintarCataleg(visibles, cataleg);
}

    export function validarFormulari(form) {
  const dades = new FormData(form);
  const errors = {};
  const equip = String(dades.get("equip") ?? "").trim();
  const correu = String(dades.get("correu") ?? "").trim();
  const participants = Number(dades.get("participants"));
  if (equip.length < 3 || equip.length > 30) errors.equip = "Escriu entre 3 i 30 caràcters.";
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(correu)) errors.correu = "Revisa el correu.";
  if (!Number.isInteger(participants) || participants < 2 || participants > 6) {
    errors.participants = "Calen entre 2 i 6 participants, sense decimals.";
  }
  if (!["tranquilla", "competitiva"].includes(dades.get("modalitat"))) {
    errors.modalitat = "Tria una modalitat.";
  }
  if (!dades.getAll("preferencies").length) errors.preferencies = "Tria una preferència.";
  if (String(dades.get("observacions") ?? "").length > 200) {
    errors.observacions = "El màxim és de 200 caràcters.";
  }
  if (!dades.has("accepta")) errors.accepta = "Cal acceptar les condicions de la simulació.";
  return errors;
}

export function guardar(ids) {

export function recuperar(cataleg) {
  try {

  }
}

      else marcadorUsuari = L.marker(coordenades).addTo(mapa).bindPopup("La teua ubicació");

      const missatges = {
        1: "Has denegat el permís. Pots continuar sense compartir la ubicació.",
        2: "No s'ha pogut determinar la ubicació.",
        3: "S'ha esgotat el temps de la petició. Torna-ho a provar."
      };
      estat.textContent = missatges[error.code] ?? "No s'ha pogut obtindre la ubicació.";
      boto.disabled = false;

    Explicació del funcionament

    Explica el recorregut d'un clic des de l'esdeveniment fins al canvi de dades, el guardat i el DOM. Després resol una modificació assignada: canviar un límit, incorporar una categoria, afegir un ordre per dificultat o mostrar un recompte per categoria. Has de poder justificar el codi encara que hages consultat les solucions.

    Exercicis breus de consolidació

    Distribuïu-los en el temps de construcció de les setmanes indicades, amb dades menudes en un fitxer de laboratori que no s'importe des de l'aplicació.

    • Setmana 1: compara let, const i var; recorre les propietats d'un repte amb for...in. Usa while per a sumar tres duracions i do...while sobre una llista d'un element; explica que aquest últim executa el cos almenys una vegada.
    • Setmana 2: sobre una còpia d'identificadors, practica push, pop, shift, unshift, splice, slice i concat. Escriu la llista resultant després de cada operació i comprova-la en consola.
    • Setmana 3: compara un fragment fix creat amb innerHTML amb nodes creats amb createElement. Mostra després el text literal <b>Equip</b> amb textContent: no ha de convertir-se en HTML.
    • Setmana 4: transforma " Equip La Vall " amb trim, majúscules, minúscules, substring, charAt, split, indexOf i replace. Compara un manejador com a propietat amb addEventListener, sense barrejar-los en la versió final.
    • Setmana 6: en una còpia del formulari, compara required, min, max, minlength, maxlength i pattern amb la validació JS. Observa :valid i :invalid i explica què aporta cadascuna. Mantín novalidate en el projecte per a l'exercici de validació pròpia.

    Límits de cobertura acordats

    Les funcions de diàleg i temporització que també apareixen en l'annex de la UD1 queden fora d'aquest projecte, d'acord amb l'exclusió del BOM. Els catàlegs d'esdeveniments de mitjans, finestra i porta-retalls són material de consulta; no són funcionalitats obligatòries. Tampoc implementarem totes les biblioteques de mapes dels apunts. El seguiment continu de la ubicació és una ampliació.

    14. Ampliacions opcionals

    • Afegir un filtre de dificultat amb un recompte de resultats.
    • Incorporar una acció per a desfer l'última eliminació.
    • Exportar i importar l'itinerari com a text JSON, validant-ne l'estructura.
    • Ressaltar en el mapa les proves seleccionades.
    • Ampliar els casos de comprovació amb proves automatitzades de les funcions de regles.

    Aquestes ampliacions es fan després de completar el flux obligatori i no canvien el termini de deu setmanes.
