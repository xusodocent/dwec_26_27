    Setmanes 7–9: JWT, rols de navegació i robustesa

    Setmana 7. Login i logout

    Objectiu: consumir l'autenticació del fake server des del client.

    Apunts: JWT, serveis, data binding.

    Pas a pas

    1. Dibuixa: credencials → POST /login → {accessToken,user} → sessió → peticions amb Bearer. El client no firma tokens ni comprova contrasenyes.
    2. Revisa login() en api.js: conserva només id, email i rol; usa currentUser() per comprovar el token amb una lectura protegida de la fitxa pròpia.
    3. Crea LoginView i afig la ruta /login al router. Usa type=password, etiquetes i autocomplete.
    4. Deshabilita el botó mentre espera, mostra l'error i buida la contrasenya després de l'intent. En aquest complement el login incorrecte retorna 400.
    5. Substitueix App.vue pel menú final. Logout neteja token/usuari i torna al catàleg.
    6. Accepta només destinacions internes conegudes en redirect; serà el guard qui decidirà si el rol hi pot entrar.
    7. Retira l'entrada manual de la consola. Prova el recorregut complet amb la interfície.

    Comprova: els dos comptes entren; una contrasenya incorrecta mostra error; el lector no veu el menú Gestió. La sessió es perd en recarregar. No es guarda cap contrasenya ni token en localStorage.

    El token de json-server-auth dura una hora. El logout elimina la còpia del client però no revoca un token copiat. Aquest complement de prototipatge té una clau de signatura de desenvolupament; no el tractem com a infraestructura d'autenticació de producció. Font: json-server-auth.

    <template><h2>Inicia sessió</h2><form @submit.prevent="entrar">
  <label>Correu <input type="email" v-model.trim="email" autocomplete="username" required></label>
  <label>Contrasenya <input type="password" v-model="password" autocomplete="current-password" required></label>
  <button :disabled="pendent">{{ pendent ? 'Comprovant…' : 'Entra' }}</button>
  <p v-if="error" role="alert">{{ error }}</p>
</form></template>
<script>
import { login } from '../services/api.js';
export default { data: () => ({ email: '', password: '', error: '', pendent: false }), methods: {
  async entrar() {
    if (this.pendent) return;
    this.pendent = true; this.error = '';
    try {
      await login(this.email, this.password);
      const dest = this.$route.query.redirect;
      // Només admetem destinacions internes conegudes.
      const safe = typeof dest === 'string' && /^\/(gestio|reptes)(\/|$)/.test(dest);
      await this.$router.replace(safe ? dest : '/reptes');
    } catch (e) { this.error = e.message; }
    finally { this.password = ''; this.pendent = false; }
  }
} };
</script>

    Setmana 8. Rols en Vue Router

    Objectiu: aprendre un contingut complementari als apunts: meta.requiresAuth, meta.roles i un guard global.

    Segueix el capítol complet de rols i router. Inclou el codi final, explicació línia a línia, matriu d'accessos i comprovacions. Crea ForbiddenView abans d'importar-lo al router.

    Fita s08: organitzador entra al panell; lector veu Accés no permés si escriu la URL; visitant acaba en login. Documenta també que un lector amb JWT pot enviar POST directament a l'API configurada amb 664: és el límit del rol de navegació.

    Setmana 9. Consultes, errors i caducitat

    Objectiu: completar el catàleg remot i gestionar fallades.

    Apunts: Promeses, AJAX exemple, cicle de vida.

    Pas a pas

    1. Completa CatalogView amb cerca, categoria, ordre i paginació de la solució de la setmana 4. Els controls envien consultes al servidor; no filtres només els quatre resultats carregats.
    2. En prémer Busca reinicia la pàgina a 1. URLSearchParams codifica accents i espais.
    3. Usa total de X-Total-Count per habilitar Anterior/Següent. Prova dues pàgines sense duplicats.
    4. Revisa càrrega, error amb reintent, buit i èxit. El buit apareix només després d'una resposta correcta.
    5. Estudia el comptador peticio: una resposta antiga no pot sobreescriure una consulta més recent. beforeUnmount() invalida respostes pendents, sense cancel·lar la petició.
    6. Atura json-server, busca, reinicia'l i reintenta. Compara error de xarxa, 404, 400 del login, 401 del token i 403 d'accés a una altra fitxa d'usuari.
    7. Usa el token caducat de backend/tokens-prova.json com a Bearer en Postman per demanar GET /users/1: ha de retornar 401. El fitxer està facilitat; no has de generar o firmar JWT.

    8. Per comprovar la recuperació del client, en el teu Vite local entra i executa:

    9. Canvia un caràcter de la signatura d'un token en Postman: una lectura protegida retorna 401. No l'envies al catàleg públic per comprovar caducitat: el catàleg no exigeix token.

    10. Revisa etiquetes, focus, ús amb teclat i missatges accessibles; prova el recorregut en dos navegadors.

    Comprova: cerca «plaça», fotografia, ordre de minuts, sense coincidències, canviar filtres des de pàgina 2, resposta antiga i reintent. El helper ha de tractar tant cossos JSON objecte com cadena.
