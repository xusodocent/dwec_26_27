    Pràctiques de JavaScript: gestor de despeses

    Construiràs Balanç, una aplicació local per a registrar despeses fictícies, consultar en què es gasten els diners i detectar errors en les dades. Començaràs amb funcions en consola i acabaràs amb una interfície que conserva la informació en recarregar.

    Són tres pràctiques progressives sobre un mateix programa, independents de qualsevol projecte del curs. Els enunciats indiquen què ha de fer l'aplicació; tu decideixes la implementació i el disseny.

    Organització

    Pràctica Continguts Temps orientatiu Resultat
    1. Analitza les despeses Variables, operadors, funcions, arrays i objectes 2–3 h Funcions comprovades en consola
    2. Construeix la interfície DOM, esdeveniments i formularis 4–5 h Aplicació interactiva
    3. Conserva i organitza JSON, localStorage, errors i mòduls 2–3 h Aplicació amb persistència

    Total orientatiu: 8–11 hores, incloses les comprovacions. Les ampliacions finals queden fora d'aquest temps. Cada pràctica continua sobre l'anterior; no cal començar tres aplicacions.

    Consulta els apunts segons el que necessites: JavaScript bàsic, DOM, esdeveniments, formularis, JSON i mòduls i emmagatzematge.

    Condicions comunes

    • Usa HTML, CSS i JavaScript, sense frameworks ni servidor de dades.
    • Treballa amb dades fictícies. No introduïsques informació bancària ni personal real.
    • Executa l'aplicació amb un servidor local, com el que ja utilitzeu a classe.
    • Usa const i let, funcions amb noms descriptius i addEventListener().
    • Les dades de l'array són l'estat de l'aplicació. Actualitza-les abans de dibuixar la pantalla.
    • Mostra els missatges a la pàgina. La consola serveix per a depurar, no com a interfície final.
    • El CSS ha de facilitar la lectura. No s'avalua la quantitat d'efectes ni cal descarregar una plantilla.

    Dades inicials i regles

    Cada despesa té un identificador únic, un concepte, una categoria i un import. Representa els diners en cèntims enters: 1250 significa 12,50 €. Fes els càlculs en cèntims i formata el resultat només en mostrar-lo.

    Copia aquest array com a punt de partida:

    const despesesInicials = [
  { id: "d1", concepte: "Compra setmanal", categoria: "alimentacio", centims: 3250 },
  { id: "d2", concepte: "Autobús", categoria: "transport", centims: 150 },
  { id: "d3", concepte: "Cinema", categoria: "oci", centims: 800 },
  { id: "d4", concepte: "Fruita", categoria: "alimentacio", centims: 675 },
  { id: "d5", concepte: "Tren", categoria: "transport", centims: 460 },
  { id: "d6", concepte: "Llibre", categoria: "oci", centims: 1490 }
];
    Dada Regla
    Identificador Cadena no buida, única i estable; no uses la posició de l'array
    Concepte Entre 3 i 60 caràcters després de llevar espais dels extrems
    Categoria alimentacio, transport, oci o altres
    Import Enter entre 1 i 100000 cèntims, ambdós inclosos
    Despeses repetides Es permeten conceptes iguals; els identificadors han de ser diferents

    La cerca ignora majúscules i espais als extrems, però no cal eliminar accents. Quan diversos registres empaten en una ordenació, conserva el seu ordre relatiu.

    Pràctica 1. Analitza les despeses

    Objectiu: escriure funcions reutilitzables que treballen sense DOM.

    1. Explora les dades

    Mostra l'array amb console.table(). Comprova els tipus de l'identificador i de l'import. Explica en un comentari per què "150" + 50 no serveix per a sumar diners.

    2. Calcula un resum

    Implementa resumeix(despeses), que retorne un objecte amb:

    • quantitat: nombre de registres.
    • totalCentims: suma dels imports.
    • mitjanaCentims: mitjana arrodonida al cèntim més pròxim.
    • maxima: objecte de la despesa més cara; en cas d'empat, el primer.

    Amb un array buit, retorna quantitat, total i mitjana iguals a 0, i maxima: null.

    Calcula primer el total amb un bucle i després amb reduce(). Compara els resultats i conserva una sola versió en el programa final.

    3. Busca, filtra i ordena

    Implementa aquestes funcions sense modificar l'array original:

    Funció Comportament
    filtra(despeses, text = "", categoria = "totes") Cerca parcial pel concepte i filtre exacte per categoria, combinats
    ordena(despeses, criteri = "import-asc") Admet import-asc, import-desc i concepte; aquest últim ordena alfabèticament en català
    totalsPerCategoria(despeses) Retorna un objecte amb les quatre categories i la suma en cèntims de cadascuna, incloent-hi les que sumen zero

    Pots assumir que les funcions reben arrays de despeses vàlides i criteris dels indicats. No cal dissenyar un sistema general per a qualsevol tipus d'entrada.

    4. Afig i elimina amb control

    Implementa afigDespesa(despeses, nova): retorna un array nou si nova compleix les regles de la taula i el seu identificador no existeix. En cas contrari, llança un Error amb un missatge comprensible. Comprova que centims és un nombre enter; no acceptes una cadena numèrica.

    Implementa eliminaDespesa(despeses, id): retorna un array nou sense el registre indicat. Si no existeix, retorna una còpia amb els mateixos registres.

    En les proves, captura els errors d'alta amb try...catch perquè pugues continuar comprovant la resta de casos.

    Comprovacions obligatòries

    Cada fila es prova sobre les dades inicials, excepte quan s'indique una altra entrada.

    Cas Resultat esperat
    Resum inicial 6 registres; total 6825; mitjana 1138; màxima d1
    Resum de [] 0 registres; total i mitjana 0; màxima null
    Totals per categoria Alimentació 3925; transport 610; oci 2290; altres 0
    Cerca " TREN " Només d5
    Text buit i categoria oci d3 i d6
    Cerca "tren" i categoria oci Array buit
    Ordre per import ascendent d2, d5, d4, d3, d6, d1
    Afegir d7, «Café», altres, 125 7 registres i total 6950
    Afegir un altre d1 Error d'identificador duplicat
    Afegir 0, -50, 12.5 o "150" com a centims Error d'import
    Afegir una categoria desconeguda o concepte " " Error de validació
    Eliminar d2 5 registres i total 6675
    Eliminar inexistent Mateixos sis registres

    Comprova també els límits 1 i 100000, que han de ser acceptats, i 100001, que s'ha de rebutjar. Després de cada operació, l'array original ha de continuar intacte.

    Entrega: codi i comprovacions.md amb els resultats obtinguts. Explicació individual: mostra una funció i explica les entrades, l'eixida i un cas límit.

    1. Mostra la informació

    Genera la llista o taula des de l'array. Mostra noms llegibles de les categories i imports amb dos decimals i símbol d'euro. Inclou un botó «Eliminar» per registre.

    Usa creació de nodes i textContent per als conceptes. La cadena <b>Prova</b> ha de mostrar-se com a text, sense convertir-se en negreta.

    2. Connecta els filtres

    • Actualitza la cerca mentre s'escriu amb input.
    • Actualitza categoria i ordenació amb change.
    • Combina els tres controls sense perdre la informació original.
    • Mostra quantitat i total dels resultats visibles, i el total global en una zona diferent.
    • El resum per categoria usa sempre totes les despeses.
    • Si no hi ha coincidències, mostra un missatge i un total visible de 0,00 €.

    3. Valida el formulari

    Inclou etiquetes associades als camps. El concepte i l'import són obligatoris; la categoria es tria amb un select.

    Per a aquest exercici, l'import és un camp de text amb inputmode="decimal". Accepta coma o punt decimal, amb un màxim de dues xifres decimals. Exemples vàlids: 12, 12,5, 12.50, 0,01 i 1000. Rebutja signes, notació exponencial, separadors de milers, text afegit i més de dos decimals.

    Normalitza els espais dels extrems i transforma l'import a cèntims abans de cridar afigDespesa(). Pots separar la part entera i decimal per a construir l'enter. No acceptes parcialment entrades com 12abc.

    Gestiona submit i evita la recàrrega. Si hi ha errors, informa al costat del formulari i porta el focus al primer camp incorrecte. Conserva els valors perquè l'usuari els puga corregir. Si tot és correcte:

    1. Genera un identificador que no col·lidisca amb els existents.
    2. Afig la despesa amb la funció de la pràctica 1.
    3. Neteja els camps i mostra un missatge d'èxit.
    4. Actualitza la pantalla mantenint els filtres actuals. Si el filtre oculta la nova despesa, indica que s'ha afegit però no coincideix amb la consulta.

    4. Gestiona l'eliminació

    Delega els clics en el contenidor de registres. Elimina mitjançant l'identificador, no mitjançant l'índex de la fila visible. Actualitza els totals sense registrar listeners duplicats.

    Els controls han de poder usar-se amb teclat. Després d'eliminar una fila, situa el focus en un control útil, com el botó d'eliminar següent o la cerca si no queden files. Usa una zona amb role="status" per als missatges de resultat.

    Acció Resultat esperat
    Obrir amb les dades inicials 6 registres; total global 68,25 €

    Escriure una cerca sense coincidències Missatge de llista buida; global sense canvis
    Afegir «Café», altres, 1,25 sense filtres 7 registres; global 69,50 €
    Afegir 12.345, 12abc, 1e2, -5, buit o 1000,01 Error; cap registre nou
    Afegir 0,01 i, en una altra prova, 1000 Imports acceptats
    Afegir amb concepte <b>Prova</b> Text literal, sense interpretar HTML
    Amb filtre transport, eliminar «Tren» de les dades inicials Queda «Autobús» visible; global 63,65 €
    Afegir una despesa d'oci amb filtre transport Es guarda en l'array i s'informa que el filtre l'oculta
    Enviar amb Enter o activar controls amb teclat Mateix comportament que amb ratolí
    Afegir i eliminar repetidament Una operació per acció, sense duplicacions

    Entrega: aplicació i comprovacions actualitzades, amb una captura que mostre un filtre i els dos totals. Explicació individual: justifica la diferència entre l'array complet i la llista visible.

    Pràctica 3. Conserva i organitza

    Objectiu: recuperar les dades i gestionar errors sense deixar la pàgina inutilitzable.

    1. Separa responsabilitats

    Organitza el codi amb mòduls. Pots adaptar els noms, però cada fitxer ha de tindre una responsabilitat clara:

  index.html
  estils.css
  js/
    dades.js          dades inicials
    regles.js         validacions, càlculs i filtres
    vista.js          creació i actualització del DOM
    persistencia.js   lectura i escriptura local
    main.js           estat i connexió de les interaccions
  README.md
  comprovacions.md

    Carrega main.js amb type="module" i usa import i export. Les regles han de continuar funcionant sense accedir al DOM ni a localStorage.

    2. Guarda després dels canvis

    Usa una única clau, balanc.despeses.v1, amb aquesta estructura serialitzada com a JSON:

    JSON
    1
2
3
4
5
6
    {
  "versio": 1,
  "despeses": [
    { "id": "d1", "concepte": "Compra setmanal", "categoria": "alimentacio", "centims": 3250 }
  ]
}

    Guarda després d'afegir o eliminar. Els filtres no canvien les despeses guardades. Recupera la informació abans del primer renderitzat.

    3. Distingeix els casos de recuperació

    Situació Comportament requerit
    La clau encara no existeix Comença amb les sis despeses d'exemple
    Guardat vàlid amb despeses: [] Mostra la llista buida; no reposa exemples
    Guardat vàlid amb registres Recupera els registres
    JSON incorrecte, versió desconeguda o estructura no vàlida Mostra un avís i arranca amb llista buida
    Un registre incompleix les regles o hi ha identificadors repetits Rebutja tot el conjunt i mostra l'avís
    Error d'accés a localStorage Permet treballar amb llista buida i informa que no es pot recuperar

    No és suficient que JSON.parse() funcione: comprova que tens un objecte, la versió correcta, un array i registres vàlids. Reutilitza les regles de validació.

    No sobreescrigues automàticament un guardat incorrecte durant l'arrancada. Una nova alta o una acció explícita de l'usuari podrà substituir-lo.

    Si falla l'escriptura, conserva el canvi en memòria i mostra que podria perdre's en recarregar. El programa no ha de quedar bloquejat.

    4. Afig dues accions explícites

    • Buidar dades: demana confirmació en una zona de la pàgina amb «Confirmar» i «Cancel·lar»; si es confirma, guarda un conjunt vàlid amb l'array buit.
    • Carregar exemples: substitueix les dades per les sis inicials després de la mateixa confirmació. No les acumula sobre les existents.

    No uses localStorage.clear(): aquesta pràctica només ha de modificar la seua clau.

    Comprovacions obligatòries

    Acció o dada guardada Resultat esperat
    Afegir una despesa i recarregar La despesa continua i el total coincideix
    Buidar, confirmar i recarregar Continua buit
    Cancel·lar el buidatge Cap canvi
    Carregar exemples dues vegades, confirmant Sempre 6 registres i 68,25 €
    Guardar manualment text incorrecte Avís i llista buida, sense error no gestionat
    Guardar null, {} o una versió 2 Avís i llista buida
    Guardar un registre amb centims: "150" o dos identificadors iguals Rebuig del conjunt
    Guardar un conjunt vàlid amb array buit Llista buida sense avís d'error
    Simular una fallada d'escriptura Canvi visible en memòria i avís de guardat

    Manipula la clau des de les eines de desenvolupament del navegador. Per a simular l'últim cas, provoca temporalment un error dins del bloc d'escriptura del mòdul de persistència; retira la simulació abans d'entregar.

    Entrega: carpeta completa, comprovacions i un README.md breu amb instruccions d'execució i limitacions conegudes. Explicació individual: diferencia un primer inici, un guardat buit i un guardat corrupte.

    Ampliacions opcionals

    Tria com a màxim una si has completat les tres pràctiques. No cal fer-les totes i no formen part de l'entrega bàsica.

    A. Editar una despesa

    Afig «Editar» i reutilitza el formulari. Conserva l'identificador, valida amb les mateixes regles i permet cancel·lar. Comprovació: canviar «Cinema» de 8 a 9 euros augmenta el total inicial a 69,25 €, sense crear un seté registre.

    B. Reordenació manual

    Afig una vista d'ordre manual amb arrossegament i botons «Pujar» i «Baixar». Desactiva els filtres en aquesta vista per a evitar ambigüitats. Modifica i guarda l'ordre de l'array. Comprovació: mou el primer registre al final, recarrega i verifica l'ordre; els totals han de ser els mateixos.

    C. Una preferència amb cookie

    Recorda amb una cookie durant set dies si l'usuari prefereix la vista compacta. Permet canviar i eliminar la preferència. Comprovació: recarregar conserva la vista; eliminar la cookie recupera la vista normal en tornar a entrar. Les despeses continuen en localStorage.

    D. Classes amb comportament

    En un fitxer independent, crea Despesa amb un mètode costAnualCentims() que retorne l'import. Crea DespesaMensual amb herència, que retorne dotze vegades l'import. Comprovació: una despesa puntual de 500 retorna 500; una mensual de 500 retorna 6000. Explica què passa amb els mètodes en serialitzar una instància a JSON. No cal canviar el model de dades de l'aplicació principal.

    Criteris de valoració

    Aplica aquesta rúbrica a les funcionalitats exigides en cada entrega:

    Criteri Punts
    Requisits funcionals i resultats correctes 4
    Validació i gestió dels casos límit previstos 2
    Codi llegible, funcions i responsabilitats clares 2
    Comprovacions documentades i explicació individual 2

    En comprovacions.md, anota entrada o acció, resultat esperat, resultat obtingut i correcció aplicada si ha fallat. No marques una prova com a superada sense executar-la. Les ampliacions no substitueixen els requisits bàsics.
